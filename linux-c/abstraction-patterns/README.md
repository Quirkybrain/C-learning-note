这个目录记录 C 语言中一些常见的抽象、封装和生命周期管理方式。

C 语言没有 `class`、`virtual`、`override` 和自动析构这些语法，但可以通过结构体、函数指针、成员偏移和明确的释放协议，组织出类似的工程抽象。

这些技巧并不属于 Linux 独有，但在 Linux 和其他开源 C 工程中经常能看到相似的设计思路，例如操作函数表、`container_of`、释放回调和分阶段资源清理。

## 系列定位

这个系列主要关注：

- C 语言如何隐藏具体数据结构。
- 如何用函数指针和函数表组织可替换行为。
- 如何在抽象指针和完整对象之间进行转换。
- 如何用明确的协议管理对象和内部资源的生命周期。

每篇笔记会尽量保持“一个核心问题 + 一份可运行示例”，通过前后版本对比观察抽象是如何逐步建立的。

## 当前内容

### 001：用函数表实现封装、抽象与多态

[阅读笔记：001-c-polymorphism-with-vtable](./001-c-polymorphism-with-vtable/README.md)

这一章通过 `Animal` / `Cat` / `Dog` 示例建立最基础的抽象模型：

- 用不透明类型隐藏具体对象结构。
- 用函数指针表描述一组公共行为。
- 用内嵌的 `Animal base` 表示公共对象部分。
- 通过对象保存的函数表指针进行运行时分发。

核心问题是：

> 调用端如何只使用统一接口，让不同类型的对象执行各自的行为？

### 002：从首成员基类到 container_of

[阅读笔记：002-c-container-of](./002-c-container-of/README.md)

这一章取消了“`base` 必须是结构体第一个成员”的隐含约束：

- 理解结构体成员相对对象起始地址的偏移量。
- 理解为什么字节级指针运算需要 `char*`。
- 用 `container_of()` 从 `Animal*` 恢复完整的 `Cat*` 或 `Dog*`。
- 让具体对象的内存布局与抽象接口解耦。

核心问题是：

> 当我们只拿到一个成员指针时，如何找回拥有这个成员的完整对象？

### 003：从多态调用到简单析构

[阅读笔记：003-c-object-lifetime-management](./003-c-object-lifetime-management/README.md)

这一章把“结束对象生命周期”也纳入抽象接口：

- 在函数表中增加销毁回调。
- 让具体类型找回并释放正确的完整对象地址。
- 让调用端只持有 `Animal*` 也能统一销毁对象。
- 通过双重指针把调用端的当前指针置为 `NULL`。

核心问题是：

> 对象的行为可以通过函数表分发，那么对象的释放能否也走同一套抽象接口？

### 004：从简单析构到析构链

[阅读笔记：004-destruct-chain](./004-destruct-chain/README.md)

这一章继续处理对象内部还拥有其他堆资源的情况：

- 将资源清理和对象本体释放拆成两个阶段。
- `cleanUp` 负责释放具体类型自己持有的资源。
- `release` 负责释放完整对象本体。
- 由抽象层固定“先清理成员，再释放对象”的顺序。

核心问题是：

> 如果对象除了自己这块内存，还拥有其他动态资源，销毁顺序应该如何组织？

### 005：从直接销毁到引用计数

[阅读笔记：005-object-lifetime](./005-object-lifetime/README.md)

这一章处理同一个对象被多个 owner 共享的情况：

- 在公共 `Animal` 对象中加入引用计数。
- 用 `animalGet()` 取得新的拥有引用。
- 用 `animalPut()` 释放当前 owner 的引用。
- 在最后一个引用消失时触发 `cleanUp + release`。

核心问题是：

> 当同一个对象被多个 owner 共享时，怎样让它一直存活到最后一个 owner 离开？

## 构建与运行

每篇笔记都是一个可独立构建的小工程，通常包含：

```text
NNN-topic-name
├── README.md   # 概念、推导过程与运行结果
├── Makefile    # 构建脚本
├── main.c      # 调用端示例
├── include     # 公开接口
└── src         # 具体实现
```

进入对应目录后执行：

```bash
make
make run
```

清理构建产物：

```bash
make clean
```

001 使用标准 C11；002 之后的 `container_of()` 学习版使用了 `typeof` 和 statement expression，因此使用 GNU C11 模式构建。

## 阅读方式

阅读时可以重点对比：

- 资源的创建与释放是否保持对称。

## 这个系列的边界

这些示例的目的是拆解 C 语言底层抽象的组成方式，而不是实现一套完整的 C 面向对象框架。

当前示例没有继续展开：

- 线程安全。
- 复杂继承关系或运行时类型信息。
- 失败路径上的完整资源回滚。

这些内容可以在后续笔记中继续扩展。当前先把一条主线讲清楚：

> 用结构体组织数据，用函数表组织行为，用成员偏移恢复对象，用明确的协议管理生命周期。
